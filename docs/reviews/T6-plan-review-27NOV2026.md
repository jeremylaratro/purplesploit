- **BLOCKER — S1’s GOAD provability is not established.** `findDelegation` confirms the delegation configuration, not vulnerability to Bronze Bit. An enforcing, patched KDC rejects the modified evidence ticket; switching the final proof to HTTP cannot fix that. **Fix:** establish the selected KDC’s susceptibility before building S1, including a positive run with `-force-forwardable` and a failing control without it. Otherwise defer S1 or use a known vulnerable lab snapshot. [Microsoft’s deployment guidance](https://support.microsoft.com/en-us/topic/kb4598347-managing-deployment-of-kerberos-s4u-changes-for-cve-2020-17049-569d60b7-3267-e2b0-7d9b-e46d770332ab).

- **HIGH — The advertised key handling can fail before either recipe produces a ticket.** Impacket requires `-hashes :<NT>` or `<LM>:<NT>`, whereas the reused [_op_auth_target](/srv/share/dev/purplesploit/.claude/worktrees/t6/python/purplesploit/validation/executors/constrained_deleg.py:115) forwards a bare NT hash unchanged. Bronze Bit additionally needs the key matching the **S4U2self ticket’s encryption type**: an NT hash cannot decrypt an AES ticket. **Fix:** normalize hash syntax, establish CASTELBLACK$’s returned ticket enctype, and supply its matching AES key when needed. Do not discard AES through the template’s hash/AES `if/elif` when both are needed. [getST implementation](https://github.com/fortra/impacket/blob/master/examples/getST.py).

- **HIGH — S2’s success predicate does not prove its claimed effect.** The template accepts either `[+]` authentication or `(Pwn3d!)`. Authentication as an impersonated user does **not** establish local admin; S4U2self preserves that user’s actual authorization. **Fix:** require successful authentication as the expected principal on the expected host **and** the admin predicate before emitting local-admin capability. Add a negative test where `[+]` appears without `Pwn3d`. North’s domain Administrator is a suitable GOAD choice if its normal admin memberships remain intact; computer-account status alone proves no admin entitlement.

- **HIGH — S2 emits the wrong capability state.** [S_computer_control](/srv/share/dev/purplesploit/.claude/worktrees/t6/python/purplesploit/validation/states.py:55) means control of an **AD computer object**, including delegation-attribute writes. It does not mean host administrator access. **Fix:** emit `local_admin_for(self_host)` after the admin proof. S1’s `S_impersonation_tgt` is appropriate—the repository explicitly defines it as a service ticket. `S0_user_creds` is acceptable when the supplied credential really is the matching service/machine key; composition from a recovered key needs a principal-bound credential capability consumed through the NT/AES channel. Preserve the resulting ticket privately for `produced()` to return `CAP_CCACHE`; a local variable inaccessible after `execute()` cannot supply that producer.

- **HIGH — S3 contains nonfunctional invocation examples and an associated masking gap.** Coercer has no `-m fsrvp` or `-m webdav`. **Fix:** pin supported filters, such as `--filter-protocol-name MS-FSRVP`. For WebDAV, select an actual RPC method with an HTTP path, specify HTTP transport/port, and establish that WebClient can send machine authentication to the matching listener. This is more than adding a method label. Coercer also uses **`--hashes`**, which [redact_argv’s flag set](/srv/share/dev/purplesploit/.claude/worktrees/t6/python/purplesploit/validation/executors/base.py:106) currently omits: add masking before storing that argv. [Coercer CLI](https://github.com/p0dalirius/Coercer/blob/master/coercer/__main__.py), [HTTP-capable EFSRPC method](https://github.com/p0dalirius/Coercer/blob/master/coercer/methods/MS_EFSR/EfsRpcOpenFileRaw.py).
