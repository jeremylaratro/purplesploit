VERDICT: FIX-FIRST

1. **BLOCKER — S2 invariant 2: “enumeration” does not define an independent authority.** A tool can report `cred_for(Administrator)` and supply a matching “DA-equivalent” finding; checking that finding would merely corroborate its own assertion. **Fix:** obtain privilege facts from an engine-owned directory resolver or independently reviewed lab truth, outside the scored executor’s outputs. Bind them to canonical domain/SID identity and relevant replication authority. Require agreement between the bound target, capability state, and credential principal. Unknown privilege may permit probing, but cannot establish `da_creds`.

2. **BLOCKER — S2 invariant 3: principal aliases can launder seed provenance.** Creating `cred_for(seed_principal)` or promoting it to `da_creds` must not stamp it with the currently executing edge’s provenance. Moreover, `_satisfied_by_escalation()` checks whether *any* satisfying state was produced, while credential routing can combine multiple entries. That does not prove the terminal used the produced credential. **Fix:** preserve immutable credential origin through aliases and promotions; select one satisfying capability atomically, including its identity, payload, and provenance. Compute escalation from that consumed capability. Principal equality with the seed alone neither establishes nor disproves genuine production.

3. **BLOCKER — S2 invariants 1/4: nonempty value plus channel is insufficient.** I reproduced an entry with `DA_CREDS`, `CAP_PRINCIPAL`, and a nonempty principal: escalation detection returns true, but DCSYNC falls back to the operator’s password because no usable authentication material was threaded. A control token could introduce the same failure. **Fix:** validate capability usability for the particular consumer. DCSYNC must receive a supported credential and its bound identity; principal names, control tokens, and service-only tickets cannot satisfy its authentication requirement. Missing composed authentication must never silently become seed authentication credited as escalation.

4. **BLOCKER — S2 invariant 4 / S3: the terminal currently permits false DA.** [DCSYNC’s predicate](/srv/share/dev/purplesploit/.claude/worktrees/validation-automation/python/purplesploit/validation/executors/dcsync.py:53) accepts the banner `Dumping Domain Credentials`. I reproduced `complete=True` and `terminal_fact.ok=True` with that banner, an access-denied error, exit status 1, and no replicated secret. The engine then treats completed DCSYNC’s static effect as reaching `S_DA`. **Fix:** require presence-only evidence of the requested krbtgt replication result from the current invocation. A banner, privilege classification, or completion flag cannot substitute for terminal evidence.

5. **HIGH — S2 design: the runtime overlay cannot discover the promised path.** With GENERIC-ALL and DCSYNC alone, search currently returns no paths even when both eligibility flags are enabled: their generic effects and preconditions do not intersect. Runtime binding happens too late. Conversely, broadly accepting `S_acl_cred` at runtime admits ordinary credentials. **Fix:** specify a planning compatibility relation or bound candidate effects that expose the potential T3→DCSYNC connection, then independently require an actual eligible product during execution. Preserve DCSYNC’s existing `dc_tgt OR da_creds` alternatives; requiring new membership enumeration for the existing DC-TGT branch would regress front→DCSYNC.

6. **HIGH — S2 invariant 1: control tokens lack lifetime and authority semantics.** WRITE-DACL, WRITE-OWNER, and ADD-MEMBER currently roll back inline before returning. Merely adding token values would publish control already removed. Also, membership in group X does not confer GenericAll over group X, and a grant to another trustee is not automatically usable by the operator. **Fix:** defer composed rollback through verified teardown obligations and describe each product’s actor, object, right, and lifetime. Consumers must check those specifics rather than accepting every `control_for(X)` interchangeably.

7. **HIGH — S1: target-only chain parameterization is incomplete.** A synthetic finding is viable, but `host=target` is not a complete technique adapter. I confirmed host-only findings fail resolution for ADD-MEMBER (`group`), TARGETED-KERBEROAST (`victim`), and CERTIFRIED (`ca`). Standalone `--param` can supply these; chain’s proposed `TECH=target` mapping cannot. Existing finding normalization also has no DCSYNC technique mapping, so filtering findings by technique would omit the terminal. **Fix:** define technique-specific input adapters, validated per-edge overrides, and explicit DC-finding construction for DCSYNC. Resolve the same bound parameters for planning and execution.

8. **HIGH — S1 secrets / S2 invariant 1: H6 is not universally enforced by `_receipt_from`.** Private artifact fields are excluded, but exception text enters receipt `errors` and chain `note` unchanged. The new credential extractor or binder could therefore leak a recovered hash by including raw output or a `Capability` representation in an exception. I confirmed receipt construction preserves a secret sentinel inside error text. **Fix:** keep recovered material in private runtime fields and use payload-free public error codes. Exercise extractor, binding, execution, and teardown failures with sentinel secrets and inspect the entire serialized receipt/report.

9. **HIGH — S2 test plan: the proposed RED checks can pass vacuously.** An implementation that never discovers T3 chains passes every negative “does not reach DA” assertion. A positive run using default edges could succeed through an existing front while T3 remains broken. **Fix:** require a positive search-and-run test whose exact path is GENERIC-ALL→DCSYNC and whose captured authentication uses the recovered credential and correct principal. Pair it with isolated negatives for non-DA/unknown authority, forged tool claims, missing credentials, unsupported channels, mismatched identities, seed aliases, and banner-only replication failure. Assert both `reached=False` and `escalation=False`; retain separate positive front→DCSYNC regression tests.
