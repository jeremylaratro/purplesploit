1. **BLOCKER — Discovery can mutate shares before either access mode starts.** [Plan L77](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:77) specifies bare `nxc --shares`. In [NetExec v1.5.1](https://github.com/Pennyw0rth/NetExec/blob/v1.5.1/nxc/protocols/smb.py#L1261), that command creates and deletes directories/files unless `--no-write-check` is set. The plan specifies neither a compatible version nor suppression of these probes. Require a verified non-mutating discovery implementation and fail closed on unsupported versions. The invariant test **can go RED** for its proposed mutant, but can remain GREEN for this real violation: no forbidden verb appears in argv.

2. **BLOCKER — Read-only access lacks a defined path-containment boundary.** [Plan L82](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:82) does not define safe handling of server-controlled names, local download destinations, or symlinks. Interpolating filenames into `smbclient -c` crosses a [semicolon-separated command parser](https://www.samba.org/samba/docs/current/man-html/smbclient.1.html), creating a potential command-injection path. In mount mode, `ro` protects the mounted filesystem; it does not confine symlink targets or cleanup operations. Require parser-safe remote operands, opaque local filenames, no-follow traversal and deletion, and a private mountpoint whose actual CIFS identity and read-only flags are verified. Neither downloads nor shredding may traverse mounted content or links into another writable share.

3. **HIGH — Calling `umount` in `finally` does not guarantee teardown or shredding.** [Plan L85](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:85) omits failed/timed-out unmounts, mount timeouts after attachment, blocked filesystem operations, and cleanup exceptions. [Unmount can fail with `EBUSY`](https://man7.org/linux/man-pages/man2/umount.2.html). Define ownership tracking, bounded worker shutdown, mount-state reconciliation, verified teardown, and independent scratch cleanup that still runs when unmount raises. Never recursively shred an attached mount. Cleanup failure must prevent a clean-success result. An “every path” guarantee also needs crash recovery and a storage design supporting the promised secret erasure.

4. **HIGH — The listed bounds do not bound actual resource consumption.** [Plan L86](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:86) omits aggregate scratch bytes, directory/entry counts, listing-output size, and a whole-run deadline. An empty-directory farm bypasses a file-count limit; recursive listing can exhaust memory before post-processing limits run. A file can grow between listing and fetch, defeating a size precheck. Require limits enforced during traversal and transfer, bounded output buffering, finite validated defaults, cycle/link handling, and timeouts covering mount-backed operations. Budget exhaustion must produce an explicit partial result.

5. **HIGH — “Location” is incorrectly treated as inherently public.** [Plan L74](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:74) permits raw paths/names in receipts, although a filename or directory component can contain a password or token. The existing [scrubber](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/python/purplesploit/validation/proof.py:64) filters field names, not secret-bearing values under `path`. Use opaque location IDs with raw mappings confined to the operator’s protected store, or an explicitly justified safe-name policy. Apply this to diagnostics and tool logs too. Secret-bearing paths must not become supposedly public proof-token inputs; hashing them does not make them public identifiers.

6. **HIGH — The proposed S1 receipt is incompatible with the current executor contract.** [Plan L87](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:87) introduces `shares_enumerated`, which is absent from [the accepted terminal kinds](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/python/purplesploit/validation/proof.py:40); receipt construction therefore drops that terminal fact. Moreover, [the base executor adapter](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/python/purplesploit/validation/executors/base.py:566) discards an inventory returned as an extra artifact field. `ValidationExecutor` reuse is feasible, but S1 needs an explicit inventory/result adapter and coordinated proof-builder/scorer/truth-contract support. Successful discovery must not be represented as credential recovery.

7. **HIGH — The success predicate can conceal incomplete scope coverage.** [Plan L87](/srv/share/dev/purplesploit/.claude/worktrees/shareloot-s1/docs/plans/PLAN-SHARELOOT-27NOV2026-smb-nfs-share-discovery-loot.md:87) allows success after one readable share is crawled, while other hosts/shares may be denied, unreachable, malformed, or truncated. That proves an existential observation, not exhaustive enumeration. Specify per-host/share outcomes and separate observed access from coverage completeness. Require positive evidence distinguishing a successfully listed empty share from failed listing, and mark mixed or bounded runs partial/inconclusive for completeness. Add fixtures for mixed success/denial, root-readable but child-denied trees, malformed output, and every truncation reason.
