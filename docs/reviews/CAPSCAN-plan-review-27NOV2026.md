VERDICT: FIX-FIRST

The separate `discover` subcommand is appropriate. With `exploit=False`, the proposed flow does not execute executors; existing `confirm()` correctly excludes confidently not-viable findings.

1. **HIGH — The destructive gate does not cover all mutations.** WRITE-DACL uses ordinary authorization, which defaults to `not_required` in an authorized lab; GENERIC-ALL’s default `shadow_creds` pivot never invokes destructive confirmation. Thus `discover --exploit --yes` can mutate AD without `--allow-destructive`. Password resets and GPO code execution do retain their runtime gates. **Fix:** enforce the promised boundary in discovery eligibility: exclude `mutating` or `destructive` executors unless `allow_destructive` is set, while retaining existing runtime gates. See [WRITE-DACL](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/executors/write_dacl.py:133) and [GENERIC-ALL](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/executors/generic_all.py:17).

2. **HIGH — Unknown synthetic candidates are automatically attempted.** The plan promises the viable set, but its test explicitly includes unknowns. Existing orchestration intentionally lets unknown—and absent—probe results proceed. With synthetic findings, a probe failure therefore permits execution without independent finding evidence, including mutation attempts described above. **Fix:** discovery auto-exploit should require a present probe with `viable=True`, `unknown=False`, and complete target parameters. Keep unknowns reportable and available for explicit manual validation. See [skip semantics](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/orchestrator.py:162).

3. **HIGH — Missing targets disappear instead of becoming unknown.** `plan()` resolves required executor parameters before probing and silently drops failures. KERBEROAST without `principal` produces no plan or probe; missing CA/group/share/GPO selectors similarly remove techniques. A fake-runner check generated 29 candidates but retained only 23, omitting ADCS-ESC1, ADD-MEMBER, CERTIFRIED, ESC11, GPO-ABUSE and OPENSHARES-WRITE. This defeats discovery coverage. **Fix:** construct discovery coverage independently of executable planning; retain every technique/host row and mark missing selectors `unknown`, non-executable. Parameter rejection currently prevents execution of these incomplete candidates; preserve that protection. See [planning](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/orchestrator.py:230).

4. **HIGH — Seeding the actor as the victim can destroy the working credential.** FORCE-CHANGE-PASSWORD takes `entity.principal` as its victim. With reset rights and `--allow-destructive`, the seeded operator account can receive a random password that is never stored, while subsequent operations continue using stale credentials. The gate permits this; it does not select a safe target. **Fix:** keep the operator as actor/trustee/member where appropriate, never as a fabricated mutation victim. Exclude the authenticated identity from destructive targets using canonical identity comparison; require an explicitly selected disposable target or report unknown. See [password-reset execution](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/executors/force_change_password.py:163).

5. **HIGH — Probe reasons are not guaranteed secret-free.** `probe_finding()` embeds raw exception text in public `reason`; `ProbeResult.to_dict()` preserves it. A runner exception containing credential-bearing argv would therefore enter the proposed report, independently of receipt scrubbing. A fake-runner sentinel check reproduced this. **Fix:** serialize fixed public error codes/messages and allowlisted typed evidence; keep raw exceptions private. Test credential sentinels on failure paths. See [exception handling](/srv/share/dev/purplesploit/.claude/worktrees/capscan/python/purplesploit/validation/probes.py:1326).
