# PurpleSploit — Offline Install

Self-contained bundle for an air-gapped **Kali Linux x86_64** box. Nothing here
touches the network.

See `VERSION` for the exact source commit and the glibc/interpreter this was
built against.

## What's in the box

| Path | What it is |
|---|---|
| `bin/purplesploit` | PyInstaller onefile binary. No Python needed on the target. |
| `wheels/` | Every Python dependency as a prebuilt wheel, including `pip`/`setuptools`/`wheel`. |
| `src/` | Full framework source (no git history, no training corpus). |
| `requirements-offline.txt` | Exact pins, generated by installing the wheelhouse offline. |
| `install.sh` | Installer. Verifies checksums, then sets up either or both forms. |
| `SHA256SUMS` | Checksums for every file in the bundle. |

## Install

```bash
tar --zstd -xf purplesploit-offline-*.tar.zst     # or tar -xzf for the .tar.gz
cd purplesploit-offline-*
./install.sh
```

That gives you two commands:

- **`purplesploit`** — the onefile binary. Fastest path, zero dependencies.
- **`purplesploit-src`** — runs from a venv against the source in
  `~/.local/opt/purplesploit/app`. Use this when you need to read or edit module
  code.

Both are installed to `~/.local/bin`; make sure that's on your `PATH`.

### Other modes

```bash
./install.sh --check                # verify integrity only, install nothing
./install.sh --binary-only          # skip the venv, just drop the binary on PATH
./install.sh --prefix /opt/purplesploit
PYTHON=python3.13 ./install.sh      # pick a specific interpreter
```

## Where state lives

The database defaults to `~/.local/share/purplesploit/purplesploit.db` for both
forms. Override with `PURPLESPLOIT_DB=/path/to.db`.

This differs from a git checkout, which puts it in `<repo>/.data/`. The onefile
binary unpacks to a temp dir that is deleted on exit, so a repo-relative default
would lose the database every run.

## Known limits

**PDF reporting needs system libraries.** WeasyPrint is bundled, but it loads
Pango/Cairo through `ctypes` at runtime, so those `.so` files cannot be vendored
into a wheel or frozen into the binary. Without them, PDF export degrades
gracefully (the import is guarded) — HTML, XLSX and DOCX reporting are
unaffected. To enable PDF on the target, stage these Kali packages ahead of
time:

```bash
apt install libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz0b libcairo2 libffi8
```

**External pentest tooling is not bundled.** PurpleSploit orchestrates
`nmap`, `netexec`, `impacket`, `feroxbuster`, `sqlmap`, `wfuzz`, `httpx`, `fzf`,
`ripgrep` and friends by shelling out to them. Those are Kali packages, out of
scope for a Python bundle. Modules that call a missing binary will report the
failure rather than crash.

**AI and OSINT modules need API access.** The `openai`, `anthropic` and `shodan`
clients are installed, but they are network clients — they will not function
air-gapped. Every other module works offline.

**Architecture and interpreter are fixed.** The wheelhouse's compiled wheels and
the binary are x86_64 and built for the interpreter recorded in `VERSION`. A
different CPU architecture, or a Python whose `cpXY` tag differs, needs a rebuild
(`packaging/offline/build-offline-bundle.sh` in the source repo).

## Verifying by hand

```bash
sha256sum -c SHA256SUMS          # from inside the bundle directory
./bin/purplesploit --version
```
